# Guild-wide report collection contract

## Goal

Prepare a reproducible guild-wide corpus for a future `BiS 25` roster calculation.

Operator target:

```text
guild label: Argentum
candidate characters: 30-40
final roster: 25
```

This document is a collection boundary, not a scoring policy. It does not assert that the current public-report endpoint can already enumerate all Argentum reports.

## Verified foundation

The current exact evidence slice contains:

```text
1 report
14 encounters
31 report actors
31 participants
1343 verified combatants parser observations
1339 actor-linked build observations
11 exact combatants actor links
```

The public report discovery mapping is verified only for one exact request:

```text
route: /api/reports/public
page: 1
limit: 5
sortBy: created_at
sortOrder: desc
observed report rows: 5
```

Verified report fields are limited to source report ID, title, timestamps, visibility and uploader. The reviewed page had null `guild_id` and `guild_name`; `/pagination`, difficulty and locations remain deferred.

## Required phases

1. **Pagination evidence**
   - capture multiple consecutive pages using the same observed query shape;
   - review the exact `/pagination` object without guessing field names;
   - prove deterministic termination and cross-page report-ID deduplication;
   - verify limit behavior before increasing the current limit of five.

2. **Guild identity binding**
   - observe a non-null source guild identifier or an independent guild identity route;
   - bind that source identity to the operator label `Argentum`;
   - do not infer guild membership from report title, uploader or nickname.

3. **Guild report manifest**
   - produce a deterministic, deduplicated report list;
   - preserve raw archive references, fetch observations and source payload hashes;
   - record time-window and completeness boundaries explicitly.

4. **Per-report evidence capture**
   - capture report, encounter and combatants payloads for every selected report;
   - normalize only through reviewed mappings;
   - persist immutable observations without mutating core identities implicitly.

5. **Multi-report character graph**
   - verify stable source actor or character identifiers across reports;
   - preserve aliases and rename history;
   - detect collisions and split identities before aggregation;
   - never use nickname alone as primary identity.

6. **Performance and global benchmark corpus**
   - collect versioned boss, difficulty, role and time-cohort observations;
   - separate performance, consistency, sample confidence and composition utility;
   - build distributions before assigning scores.

7. **BiS 25 roster optimization**
   - select 25 from the verified 30-40 character pool;
   - enforce role, encounter, utility and availability constraints;
   - publish confidence, selection reasons, reserves and composition risks;
   - keep the scoring policy versioned and auditable.
