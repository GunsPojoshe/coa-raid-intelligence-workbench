# E0-001 — Approved 25-player regression fixture

## Цель

Зафиксировать один утверждённый заполненный состав на 25 игроков и ожидаемые результаты Excel v9, чтобы изменения формул и перенос scoring в Python можно было проверять автоматически.

## Вход

- 25 строк: slot, player, class, spec, quantity;
- значения legacy controls: recommendation role, scoring profile, uniqueness, max spec, max class, raid profile;
- выбранные два варианта на листе сравнения;
- подтверждение того, что книга пересчитана в настольном Excel и сохранена с актуальными cached values.

## Ожидаемый golden output

- роль и validation каждой строки;
- counted players = 25;
- coverage по всем 45 эффектам;
- число отсутствующих критичных/всех эффектов и readiness;
- Top-10 кандидатов и объяснение кандидата №1;
- результат сравнения двух специализаций;
- версия Excel и checksum пересчитанной книги.

## Acceptance tests

1. Fixture содержит ровно 25 активных уникальных слотов.
2. Каждая class/spec pair присутствует в `RawCombinationsTable` ровно один раз.
3. Повторный extraction из той же книги создаёт идентичный JSON.
4. Workbook v10 в режиме 25 совпадает с утверждённым fixture либо содержит документированное принятое расхождение.
5. Изменение режима на 10/40/FLEX не удаляет значения строк 11–40 и не влияет на расчёт неактивных строк.

## Технический prerequisite: repair candidate

До заполнения утверждённого состава создан воспроизводимый кандидат
`workbook/candidates/CoA_Raid_Comp_Конструктор_v9_formula_repair.xlsx`.

Кандидат исправляет только ошибочные OOXML-префиксы функций `TEXTJOIN` и `RANK.EQ` и включает полный пересчёт при открытии. Он не содержит утверждённый состав на 25 и не закрывает E0-001. После пересчёта в настольном Excel результат должен быть извлечён в golden JSON и отдельно утверждён.
